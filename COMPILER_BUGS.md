# COMPILER_BUGS

- Returning a `Backend` interface value from a helper function and then calling a method on it can fail in C selfhost with `rtg c backend error: interface dispatch failed` (repro: `selfhost-c` with `getRegisteredBackend(...) (Backend, error)` pattern).
- Methods with unnamed receiver identifiers (for example `func (T) M()`) are rejected by the parser during selfhost (`expected type, got )`), so receiver names are currently required.
- Calling `err.Error()` from some helper-returned `error` values can fail selfhost codegen with unresolved call `err.Error`, so new CLI helper paths should avoid requiring interface method calls for diagnostic printing.
- Threading `DriverOptions` as an extra parameter into helper-only paths can trigger selfhost instability (`cmp build/stage2 build/stage3` mismatch) even when behavior is unchanged, indicating a codegen nondeterminism bug in option-plumbing-sensitive call paths.
- Calling a function-typed parameter from helper wrappers in compiler code (for example `fn()`) can fail selfhost codegen with `unresolved calls: fn`, so higher-order helper patterns are currently unsafe in refactor scaffolding.
- Repeated apply/restore wrapper helpers around frontend phases can trigger deterministic selfhost drift (`cmp build/stage2 build/stage3` mismatch around byte 48228) despite no semantic change, indicating another codegen-stability issue tied to helperized option-scoping control flow.
- Introducing/using a dedicated `frontendOptionsFromDriver(...)` conversion path in `main` can also trigger deterministic selfhost stage drift (`cmp` mismatch around byte 48163), suggesting frontend option conversion helpers currently perturb codegen stability.
- Replacing backend registry enum/switch dispatch with direct `Backend` interface instances in a map can trigger deterministic selfhost drift (`cmp` mismatch around byte 43889), indicating interface-valued registry lookups currently perturb codegen stability.
- WASM->native cross-selfhost can deterministically drift on GitHub Ubuntu runners (`cross_stage3` vs `cross_stage4`, first diff near byte 46616 in `.text` inside `main.init$globals`), indicating environment-sensitive codegen instability in global-init emission paths.
- In failing WASM cross-selfhost artifacts, `main.init$globals` can pair embed file names with wrong file contents (e.g. `runtime/runtime_linux_amd64.go` name with WASI runtime source bytes), causing deterministic stage drift from corrupted embed name/data associations.
- Switching compiler embed loading to prefer disk walk (`walkEmbedDir`) before embedded FS currently triggers native selfhost drift (`cmp build/stage2 build/stage3` mismatch around byte 43808), indicating another codegen-sensitivity edge in embed-init path plumbing.
- Native backend refactors that route codegen through function-typed helper parameters (`compileFunc`, `emitTostringHelper`, `patchAt`) can fail selfhost with unresolved calls to those parameter names, so callback-style helpers remain unsafe in compiler code.
- Collapsing multiple native generator entrypoints into a single profile-driven helper can trigger deterministic selfhost drift (`cmp build/stage2 build/stage3` mismatch around byte 46368), indicating compiler codegen is sensitive to this additional helperized control flow.
- Switching `main` to call frontend compilation via a `Frontend` interface value can crash native selfhost stage1 (`./build/stage1 ...` exits 139), indicating interface-based frontend dispatch in the compiler driver is currently codegen-unstable.
- Dispatching native target generation through function values loaded from a map can fail selfhost with unresolved calls to the local function variable name (`unresolved calls: gen`), so function-valued target dispatch is currently unsafe in compiler code.
